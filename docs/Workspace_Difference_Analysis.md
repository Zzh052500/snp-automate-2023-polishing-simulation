```xml
<!-- launch/start.launch.xml -->
```

## 三、真正的差异点（风险实际所在）

虽然半径一致，但以下三点才是需要投入工作的地方：

### 差异点 1：关节范围 ±360° 带来的 IK 多解问题 🔴

**这是最大的技术风险，且与前一份文档的判断方向相反。**

```
HC10DT 关节范围（典型协作机器人）:
  J1~J6:  ±180° 左右

CR12A 关节范围（官方）:
  J1/J2/J4/J5/J6:  ±360°   ← 注意！
  J3:              ±160°
```

#### 为什么 ±360° 反而危险？

```
±180° 时：
  目标 θ = 10°  → 唯一解 10°
  IK 求解结果确定

±360° 时：
  目标 θ = 10°  → 解可以是 10°、370°、-350°、730°...
  IK 有无穷多组解！
```

#### 具体故障模式

**模式 1：关节绕整圈**

```
打磨路径相邻两点:
  Point_1 求解 → θ2 = 355°
  Point_2 求解 → θ2 = 5°     (数学上等价，但物理上要转 350°)

Descartes / MoveIt 规划器看到:
  θ2: 355° → 5°  =  -350° 的大幅运动 ⚠️

实际现象:
  机械臂在打磨过程中突然"绕一整圈"
  路径执行时间暴增
  可能与工件/夹具发生碰撞
```

**模式 2：路径不连续导致求解失败**

```
Descartes 求解器要求相邻路径点的解是"连续的"
  ↓
±360° 下 KDL 可能返回不连续解（差 360°）
  ↓
LadderGraphSolver failed to build graph  ← 当前项目踩过的坑！
```

> 注：`LadderGraphSolver failed to build graph` 这个错误在当前 HC10 配置中也出现过，
> 当时的解法是"法向量写死为朝上 (0,0,1)"。换成 CR12A 后，
> **±360° 会让这个问题更容易复现**。

#### 应对措施

```xml
<!-- 在 CR12A 的 URDF 中人为收窄关节范围 -->
<joint name="cr12a_joint_1" type="revolute">
  <limit lower="-3.14159" upper="3.14159" effort="..." velocity="..."/>
  <!-- 从 ±2π 收窄到 ±π，消除多圈歧义 -->
</joint>
```

| 措施 | 说明 | 代价 |
|------|------|------|
| 收窄 URDF 关节限制 | 把 ±360° 人为限制为 ±180° | 损失部分灵活性，但路径唯一 |
| 启用关节连续性约束 | 在 Tesseract 中配置 continuity | 配置复杂 |
| 后处理关节角 | 对 IK 解做 unwrap，保证相邻点连续 | 需要自研代码 |

**预计工作量：4-6 小时**

### 差异点 2：底座安装接口必须重做 🔴

在 `urdf/workcell.xacro` 中发现了**硬件专用件**：

```xml
<!-- 第 108、144 行 -->
<mesh filename="package://snp_automate_2023/meshes/collision/hc10_standoff.ply"/>
```

这个 `hc10_standoff.ply` 是 **HC10 专用的安装过渡板**，用于连接：

```
ATI 力控主轴 (ati_spindle / ati_tool / ati_hose)
    ↓
ati_bracket + ati_standoff
    ↓
hc10_standoff          ← 🔴 HC10 专用！换 CR12A 必须重做
    ↓
sensor_bracket
    ↓
tool0
```

#### 需要确认的接口参数

| 参数 | HC10DT | CR12A | 需要动作 |
|------|--------|-------|---------|
| 法兰直径 | 待实测 | 待实测 | 实测确认 |
| 法兰螺栓孔 | 待实测 | 待实测 | 实测确认 |
| 法兰到 tool0 偏移 | hc10_standoff 决定 | **未知** | **重新设计过渡板** |
| 定位销 | 有/无 | 有/无 | 实测确认 |

#### 影响

```
如果接口不匹配:
  ❌ 工具无法物理安装（真实场景）
  ✅ 仿真中需重新定义 flange → tool0 的固定变换
  ❌ TCP 位置改变 → 打磨接触点偏移
```

**预计工作量：3-5 小时**（含建模 + 仿真验证）

### 差异点 3：Z 轴工作范围偏移 🟡

```
当前配置:
  ir_min_z: 0.0889 m
  ir_max_z: 0.527 m
```

这两个值与**底座安装高度**直接相关。若 CR12A 底座高度不同：

```
假设 CR12A 底座高出 Δh:
  新的可达 Z 范围 = [0.0889 + Δh, 0.527 + Δh]

  工件 Z = 0.302~0.317 m（固定不变）

  如果 Δh 太大 → 工件可能落在下边界附近
               → 腕部姿态受限
```

#### 需要实测的数据

```bash
# 仿真中测量（启动后执行）
ros2 run tf2_ros tf2_echo base_link tool0

# 或直接看 URDF 中 base_link 相对 world 的位置
grep -A5 "base_link" urdf/workcell.xacro | grep -i origin
```

**预计工作量：1-2 小时**

## 四、修正后的风险矩阵

| 风险点 | 前一版评估 | **修正后评估** | 变化 |
|--------|-----------|--------------|------|
| 工作空间**大小**不足 | 40% 🔴 | **~5%** 🟢 | ⬇️ 大幅下调 |
| 关节范围 ±360° 多解 | 未识别 | **60%** 🔴 | ⬆️ 新发现 |
| 安装接口不匹配 | 未识别 | **80%** 🔴 | ⬆️ 新发现 |
| Z 轴范围偏移 | 40% 🔴 | **20%** 🟡 | ⬇️ 下调 |

### 关键结论

```
❌ 原来的担心（臂长缩短导致边缘够不到）—— 不成立
   两者有效半径都是 1200mm，工件仅在 0.73~1.00m 处

✅ 真正的工作量在：
   1. ±360° 关节导致 IK 多解（需要收窄或加连续性约束）
   2. hc10_standoff 专属件需要重新设计
   3. 底座高度差异需要重新标定 ir_min_z / ir_max_z
```
